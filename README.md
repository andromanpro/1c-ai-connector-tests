# Тесты ИИконы

Тестовое расширение YAxUnit для [ИИконы](https://github.com/andromanpro/1c-ai-connector).
Версия исходников 1.6.3 соответствует тегу `v1.6.3` продукта. В 24 модулях проверяются
ядро, форматы провайдеров, вложения, агентская петля, RAG, мониторинг, MCP, диаграммы,
парсеры и контроль персональных данных.

## Проверенный набор для 1.6.3

653 серверных теста из 23 модулей и 12 клиентских проверок: без падений, ошибок и пропусков.
После исправления новых тестов повторены 125 проверок ядра. Семь зависящих от окружения
сценариев исключены из явного состава прогона; это не успешные или пропущенные тесты.
Состав и причины — в tools/legacy-regression-selection.json. Платных вызовов не было.

17 новых проверок ядра используют настоящий HTTP-транспорт с локальными ответами.
Для них поставляются qdrant_fixture.py, diagram_fixture.py и legacy_model_fixture.py.
Запускайте в отдельной проверочной базе с ИИконой 1.6.3, YAxUnit 25.12 и этим расширением.
Скрипты используют блокировку базы, проверяют чужие процессы и свежесть JUnit по уникальному
каталогу, точный состав тестов, ошибки, пропуски и завершение собственного клиента.

```text
py -3.14 tools/run-legacy-regression-tests.py --base-path "<отдельная база>" --output-root "<новые отчёты>"
py -3.14 tools/run-warning-form-tests.py --base-path "<отдельная база>" --output-root "<новые отчёты форм>"
```

Нужны Windows, Python 3.14 и pywin32. Перед запуском ознакомьтесь с составом проверок.
Общий запуск без явного отбора может обратиться к живым сервисам при наличии настроек.
47 замечаний Sonar к прежним строкам старого ядра и долг типов EDT остаются отдельной работой;
этот выпуск не объявляет весь тестовый код статически чистым.

### Исторический прогон 1.6.2

Контрольный прогон: **461 тест, 455 успешно, 0 ошибок, 6 пропусков**.
Пять проверок требуют локального сервиса распознавания имен, который в этом прогоне
не был запущен. Один сценарий отсутствующих реквизитов MCP пропущен, потому что в
проверочной базе они уже заполнены. Пропуски не считаются успешными проверками.

Выполнены только десять модулей ниже. Полный набор включает тесты, вызывающие
настоящий API провайдера при наличии ключа, поэтому его нельзя считать полностью
изолированным от сети или расходов. Наличие исходника теста не означает его свежий прогон.

## Как прогнать контрольный набор

1. В отдельную базу с ИИконой 1.6.2 загрузите [YAxUnit](https://github.com/bia-technologies/yaxunit)
   и это тестовое расширение. Мониторинг ошибок и уведомления в этой базе выключите:
   ожидаемые ошибки тестов могут попасть в журнал регистрации без стека.
2. Сохраните конфигурацию YAxUnit, подставив свой путь отчета:

```json
{
  "reportFormat": "jUnit",
  "reportPath": "<путь-к-отчету.xml>",
  "filter": {
    "modules": [
      "Тесты_КИИ_Ядро",
      "Тесты_КИИ_RAG",
      "Тесты_КИИ_RAGQdrant",
      "Тесты_КИИ_ГенераторДиаграмм",
      "Тесты_КИИ_КонтрольПерсональныхДанных",
      "Тесты_КИИ_ПравилаПерсональныхДанных",
      "Тесты_КИИ_МониторингОшибокДашборд",
      "Тесты_КИИ_МониторингОшибок",
      "Тесты_КИИ_СерверMCPAuth",
      "Тесты_КИИ_МаркдаунПарсер"
    ]
  }
}
```

3. Запустите 1С с параметром `/C"RunUnitTests=<config.json>"`. Пример:

```text
1cv8 ENTERPRISE /F"<база>" /N"<пользователь>" /C"RunUnitTests=<config.json>"
```

Результат зависит от состояния базы: проверяйте каждый пропуск по отчету.
Исторический полный прогон 1.6.1 содержал 570 тестов; его результат не переносится
на текущую версию автоматически.

## Состав и данные

- `src/CommonModules/Тесты_*` — тестовые модули;
- `ИсполняемыеСценарии()` регистрирует наборы через `ЮТТесты`;
- утверждения используют `ЮТест.ОжидаетЧто(...)`.

Тесты с проверочными записями очищают свои данные. Исключение —
`РегламентыОчистки_СоздаютсяИНеДублируются`: он создает недостающие штатные задания
очистки кеша, аудита MCP и журнала контроля персональных данных; задания остаются.
