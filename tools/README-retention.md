# Хранение временных окружений EDT

Экспортёр создаёт отдельные `cli-configuration` и `workspace` для каждого
запуска. После завершения процесса по умолчанию удаляются только воспроизводимые
кэши `cli-configuration/org.eclipse.osgi` и
`workspace/.metadata/.plugins/com._1c.g5.v8.dt.core/bm-model-manager`.
Это выполняется также при ошибке экспорта или проверки после завершения JVM.

Исходный архив, снимки проектов, XML-выгрузки, сборки, консольный журнал,
`workspace/.metadata/.log` и остальные результаты сохраняются.
Очистка записывается в `edt-export-retention.json`. Ошибки удаления остаются
явными в этой квитанции. Продуктовые результаты не подменяются результатом очистки.

Если ожидание процесса было прервано и завершение JVM не подтверждено,
кэши автоматически не удаляются. Каталоги с рабочими блокировками Windows
и пути с символическими ссылками или junction также не удаляются.

Для сохранения полного окружения при целевой диагностике используется
`--keep-workspace` в CLI либо `keep_workspace=True` при вызове `export()`.
Такое сохранение является явным исключением из обычной политики.
По умолчанию тяжёлые окружения ошибок не накапливаются; их журналы сохраняются.

Изменение оснастки образует новый состав входов проверки. Старые квитанции
и результаты не следует приписывать исходникам с изменённым экспортёром.
