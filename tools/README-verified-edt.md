# Постоянный запуск проверенного состава через EDT

`verified_yaxunit.py --edt-project` доставляет выбранные расширения через штатный
API EDT и вызывает `run_yaxunit_tests`. Команду клиента и пути настроек формирует
MCP. Полный экспорт и повторный импорт конфигурации не выполняются.

Нужны Windows, Python 3.14, pywin32, psutil, открытая EDT с привязанной тестовой
базой и CodePilot с параметрами `tests`, `expected_contexts`, `allow_all_tests`
(в форке — сборка `1.3.9.20261031-1259` и новее). Схема реально установленного
MCP проверяется до доставки. Движок YAxUnit уже должен быть установлен.

```text
py -3.14 tools/verified_yaxunit.py --edt-project <базовый-проект>
  --base-config <закрытый-файл-настроек.json> --plan <план.json>
  --output-root <каталог-квитанций> --mcp-helper <edt_call.py> --timeout 600
```

Аргументы команды передаются в одной строке. Закрытый файл настроек хранится вне
репозитория; содержит connection, cluster, infobase, lease_key и platform_bin.
Учетные данные не передаются в командной строке Python. Пример плана:

```json
{
  "roots": {"product": "<исходники-продукта>", "tests": "<исходники-тестов>",
            "mechanism": "<репозиторий-тестов>/tools"},
  "extensions": {"Продукт": "База.Продукт", "Тесты": "База.Тесты"},
  "tests": ["Тесты_Хранение.Сохранение"],
  "test_contexts": {"Тесты_Хранение.Сохранение": "Сервер"}
}
```

План фиксирует точные имена выполнений, включая параметры. Допустимые контексты:
Сервер и КлиентУправляемоеПриложение. Общее количество не заменяет сверку имен.

До запуска оснастка проверяет целевую базу и сеансы, получает блокировку,
фиксирует исходники, доставляет каждое расширение через dry-run/update/status и
читает установленный CFE. Служебный агент EDT распознается по базе, режиму
AgentMode, PID, времени создания, родителю 1cedt.exe и единственному подходящему
сеансу Конфигуратора на том же компьютере. Неизвестный сеанс останавливает запуск.

Постоянные локальные имитаторы включаются на время прогона. Их результаты,
запрос MCP, жизненный цикл клиента, свежий JUnit и CFE до/после сохраняются в новой
квитанции. Изменение исходников во время прогона, другая база, измененный CFE,
неполный состав, другой контекст или пропуск не принимаются за успешную проверку.

Доставка может занимать до 10 минут после холодного запуска EDT. При таймауте
чтения повторяется только проверка статуса известного задания. Мутация никогда
не повторяется автоматически: неопределенный исход сохраняется, сначала нужно
установить состояние прежнего задания. По коду клиента 0 успех не определяется.

Проверки самой оснастки: `py -3.14 -m unittest discover -s tools -p "test_*.py"`.
Сертификат успешного прогона — `junit-verified.json` конкретного каталога,
а не старая запись README или просто наличие окна 1С.
